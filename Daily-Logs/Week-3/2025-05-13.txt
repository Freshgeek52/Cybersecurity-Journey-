Data Backup and Recovery Basics
===============================
1.1 Core Concepts
-----------------
Data backup and recovery refers to the process of creating copies of computer data for the purpose of restoring the original data in the event that it is lost, damaged, or otherwise rendered unavailable. This process is critical to supporting the Availability pillar of the CIA Triad (Confidentiality, Integrity, and Availability) - meaning that data should always be accessible to those with permission to use it.

Likewise, data backup and recovery is also key to Business Continuity - the ability of an organization to continue functioning at acceptable levels during and after a disruptive event. One of the most important functions of Business Continuity is Disaster Recovery, which deals specifically with maintaining or restoring critical IT infrastructure following a disaster (whether natural or man-made) with as little loss of function and data as possible. When developing a Business Continuity Plan (BCP) or Disaster Recovery Plan (DRP) - formal documents created to contemplate an organization’s business continuity and disaster recovery functions - detailed data backup and recovery processes and procedures are among the first and most important details that must be accounted for, including what data must be backed up, with how many copies, in how many locations, and with which type of backup.

Types of Backups
There are six types of backups:

Full
Differential
Incremental
Synthetic full
Continuous
Bare metal

>>> Full backups are the easiest to understand: all files and folders on a given system are backed up. However, full backups are time- and resource-intensive, in terms of disk, tape, cloud storage, network bandwidth, etc. required to support the backup. For this reason, full backups are commonly combined with both differential and incremental backups.

>>> A differential backup backs up all files that are new or have changed since the last full backup. Incremental backups are the most granular. The first incremental backup backs up all files that are new or have changed since the previous full backup, then all subsequent incremental backups only back up what is new or has changed since the last incremental backup.

In the example above, admins take a full backup on Friday, then differential backups are taken Monday through Thursday. If there is an issue on Thursday, Friday’s backup plus the differential from Wednesday is used to restore data. Any data created after Wednesday’s backup is lost in this scenario. Only the full backup plus a single differential backup is needed to restore files.

>>> In this next example, admins again create a full backup on Friday, then incremental backups are taken Monday through Thursday. If data is lost on Thursday, the full backup from Friday plus the incremental backups from Monday, Tuesday, and Wednesday are used to restore the data. Any data created after Wednesday’s backup is also lost in this scenario. It takes the full backup plus all the incremental backups to restore data.

Note: The risk tolerance for data loss is part of the organization's Recovery Point Objective (RPO). The RPO dictates how much data loss is acceptable. If the system in this example does not change frequently, losing a day or more may have no real consequences. However, suppose the risk of losing a full day’s data is too great. In that case, the organization can augment daily backups with hourly backups - for example, weekly full backups, daily differential backups, and hourly incremental backups. Ultimately, the organization must balance the cost and time of backing up systems and data with the risk of data loss.

Some backup providers, especially cloud providers, offer continuous and synthetic full backups. Continuous backups push new data to storage on an ongoing basis once a single full backup is taken. Synthetic full backups are created by combining past backups (last full plus any differential or incremental backups) and only grabbing the most recent new or changed files. In other words, data in storage is duplicated into a new full backup so that only the most recent files are needed from the server. In this way, you get the benefit of a full backup (only one backup to restore) for the cost of an incremental backup. 

>>> Bare metal backups are a type of full backup. A bare metal backup can restore a complete server (OS, applications, and data) to new hardware or virtual machine. The primary use for this today is when the application running on the server or virtual machine cannot be reinstalled easily (if at all). Bare metal backups are also used to upgrade end-user desktops and laptops. Administrators use bare metal backups to migrate from physical hardware to virtual or cloud-based images.

Antivirus Basics
================
1.1 Core Concepts
-----------------
he term malware is short for malicious software - typically, that means software that is designed to disrupt the normal operations of a computer or computer network, or otherwise compromise one or more elements of the CIA triad (Confidentiality, Integrity, Availability). Malware has many varieties, including: worms, viruses, trojans, spyware, adware, keyloggers, ransomware, and cryptojacking software. However, software does not need to be destructive to be considered malware. Broadly speaking, any software that acts for the purpose of another and not for the user is considered malware.

Software that detects and removes malware is known as antivirus or anti-malware. Antivirus software can scan files, monitor a system in real-time, quarantine files, and even work with AI and EDR systems to automate a response.

Malware Detection Techniques
There are four major types of malware detection techniques employed by antivirus solutions:

Signature-based antivirus is the most common. Signature-based antivirus looks for patterns in known malware and quarantines files based on those patterns. New signatures must be added to the local antivirus engine as new viruses are developed. Thus signature-based antivirus needs to be updated regularly to stay effective and current. 
Heuristic antivirus uses static and dynamic analysis to determine if software contains malware. Heuristic antivirus runs suspected code in a sandbox to see how it behaves. The advantage of heuristic antivirus is that it can detect new or novel malware. The disadvantage is that heuristic analysis is resource intensive and prone to false positives. Many vendors combine signature-based detection with heuristic detection to reduce the impact on performance.
Behavior-based antivirus is a heuristic antivirus that focuses more on what the malware does than the malware code itself. If the code says "cow", yet the malware quacks, then behavioral analysis says it is a duck. A behavioral engine will also try to establish a baseline for what is "normal" and take action when something deviates from this. A purely heuristic system is more concerned with indicators of compromise (e.g., evil IPs, known libraries, etc.)
Adaptive antivirus has many marketing names. Some vendors tout machine learning, and others claim to have artificial intelligence. Adaptive antivirus is both heuristic and behavioral. It can learn and adapt to new forms of malware and create new signatures as needed. Adaptive antivirus systems can also share information so that new malware signatures created on one system are shared with other systems.
Microsoft Defender Antivirus
The default antivirus solution for Windows systems is Microsoft Defender Antivirus. Microsoft has come a long way regarding endpoint protection, which makes sense given that Windows systems are generally the preferred malware target. The current incarnation of Microsoft Antivirus is primarily signature-based. Those who buy Microsoft 365 E3 or E5 get Microsoft Defender for Endpoint included. Endpoint adds adaptive analysis, EDR features, and central management to Windows Defender. Microsoft Defender is lightweight and very effective for most users as a stand-alone anti-virus.
